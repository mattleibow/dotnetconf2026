# Spec-Driven Development with GitHub Copilot, Coding without losing the Plot

AI can write code faster than ever. The catch is that it does exactly what you ask in the moment and forgets why. Ask twice and you get two different answers. Come back a month later and nobody remembers what the code was meant to do. It’s like a band improvising every night with no sheet music: great in the moment, impossible to repeat.

Spec-driven development gives the band a score. You write down what you want and why, in plain language, and that becomes the reference point the AI builds from. When requirements change, you change the score, not the code.

In this session we’ll do exactly that, live. Using GitHub Spec Kit with Copilot, we’ll take an idea from a written spec to a working .NET 11 service. We’ll set the project’s ground rules, plan the work, break it into tasks and let Copilot build it, with tests to prove it does what the spec says. Then we’ll change one requirement and watch everything follow.

Along the way we’ll cover when a spec is worth the effort and when a quick prompt is enough, how to stop the spec and the code drifting apart, and how to review AI-written code without rubber-stamping it.

You’ll leave with a repeatable workflow, a starter template and the demo repo.
